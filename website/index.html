Lazy & ordered

Transform now.
Enumerate when ready.

Filter and Map defer work until enumeration. Map between different types without losing inference.

Indexed callbacks are available too. Use Map((value, index) => ...) when position matters.

Typed transformations
using CollectionIterable;

var names = new[] { "Ada", "Linus", "Grace" };
var labels = names
    .Filter(name => name.Length > 3)
    .Map((name, index) => $"{index + 1}. {name}")
    .ToArray();

// ["1. Linus", "2. Grace"]
Awaitable completion

Offload CPU work.
Observe completion.

FilterAsync runs a synchronous predicate on a worker thread and materializes the result before the task completes.

These are CPU offloading helpers. For asynchronous I/O, use native async APIs; do not pass async-void callbacks.

Await a completed result
using CollectionIterableAsync;

var numbers = new[] { 1, 2, 3, 4, 5, 6 };
var evens = await numbers.FilterAsync(n => n % 2 == 0);

// Work is finished when await returns.
// evens contains 2, 4, 6.
Concurrent callbacks

Control concurrency.
Keep cancellation explicit.

Use IIterableOptions to set the degree of parallelism and a cancellation token.

Parallel filter results are unordered. Callbacks must be safe to run concurrently; more threads are not automatically faster.

Bounded parallel filtering
using CollectionIterableParallel;
using CollectionIterableUtils;

using var cancellation = new CancellationTokenSource();
var options = new IIterableOptions
{
    parallelOptions = new ParallelOptions
    {
        MaxDegreeOfParallelism = 4
    },
    cancellationToken = cancellation.Token
};
var evens = new[] { 1, 2, 3, 4, 5, 6 }
    .FilterParallel(n => n % 2 == 0, options);

// Contains 2, 4, 6. Order is unspecified.

Cancellation & concurrency
Cancellation is cooperative. Either supplied token can cancel; options are copied, never mutated. Default maximum parallelism is five.

Upgrading from 1.0.2

A fresh version.
A few deliberate changes.

Version 2.0.0 changes the Map API and tightens completion and cancellation behavior. Rebuild consumers and review these contracts.

Map supports different input and output types

Inferred calls such as .Map(x => x + 1) still work. Replace explicit .Map<int>(...) with .Map<int, int>(...), or let C# infer both types.

Async results finish before await returns

FilterAsync and general-enumerable ConcatAsync materialize their results before completing. This changes exception timing and memory lifetime.

Cancellation and errors are observable

Registered parallel cancellation raises OperationCanceledException directly. Callback failures remain observable; dictionary merge and key failures may surface directly after callback processing.

Await parallel iteration

The legacy void CollectionIterableAsync.ForeachParallel methods are obsolete. Use ForEachParallelAsync and await the task to observe completion and errors.

Review validation and sort assumptions

Framework-backed methods use framework argument validation. Sorts cache keys; comparator exception wrapping, null-key handling, and equal-key ordering can change. Keep selectors pure.
